Contextualização

Uma equipe comercial controla clientes, produtos e vendas em planilhas e perde pedidos por erros simples: cliente sem cidade, produto com preço zero, venda acima do estoque e acesso de usuários que já foram desligados. Antes de trocar a planilha por um CRM, o gestor exige que cada parte do sistema nasça com testes automatizados, para que uma alteração futura não quebre o que já funciona (teste de regressão).

O CRM é um projeto Vite com uma página principal (index.html) e um arquivo JavaScript por assunto. O banco é um json-server local (arquivo db.json, iniciado com npm run api) acessado pela Fetch API em api.js (listar, buscar, criar, atualizar, remover). O menu Config guarda o endereço desse banco. Login de entrada: usuário aluno, senha aluno.

Desafio

Você, como aluno consultor, foi chamado para garantir a qualidade do CRM. Complete o projeto fornecido e escreva um arquivo de teste para cada arquivo de código, seguindo o padrão AAA (Arrange, Act, Assert), usando o matcher mais específico em cada verificação e cobrindo os valores-limite. Nos testes de login.js e pedido.js, substitua dependências por mocks.

Regra do projeto: não use async/await — encadeie o fetch com .then() e receba as dependências (a API, o fetch, o relógio) por parâmetro.

Resultados esperados

  • Projeto Vite do CRM rodando (npm run dev) com login, menu, clientes, produtos, pedidos e usuários.
  • Um .test.js para cada arquivo: api, api-falsa, config, pdf-atividade, tela, cliente, produto, pedido, usuario, login e menu.
  • No mínimo 3 testes por arquivo, incluindo bordas (idade 0 e 120, estoque 0, status 0 e 1).
  • Print do terminal com npm run test:run e todos os testes passando.

Passo a passo

  1. Passo 0 (35 min): criar o projeto e rodar o primeiro teste. 
    npm create vite@latest crm -- --template vanilla
cd crm
npm install -D vitest jsdom
npm pkg set scripts.test="vitest" scripts.test:run="vitest run"
    No vite.config.js use test: { environment: 'jsdom' }.
  2. Suba o banco com npm i -D json-server@0.17.4 e npm run api; escreva api.js e api.test.js (com fetch falso). Rode npm test (modo observação).
  3. Repita a dupla arquivo + teste para cliente, produto, usuario, login, pedido, menu e tela, nessa ordem.
  4. Monte o index.html e o main.js ligando login → menu → telas.
  5. Dinâmica "Mutante sobrevivente" (25 min): a dupla A troca >= por > (ou um valor fixo) no código da dupla B; se nenhum teste falhar, a dupla B escreve o teste que faltava.
  6. Tire o print de npm run test:run e entregue o projeto (sem node_modules).
